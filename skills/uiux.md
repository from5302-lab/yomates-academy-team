# 학원 화면 UI/UX 점검

학부모는 거의 휴대폰으로 본다. 휴대폰에서 먼저 맞추고 PC를 맞춘다. '봤다'가 아니라 '쟀다'로 보고한다.

## 1. 만들기 전 (설계 한 장)
- 이 화면의 주인공 하나만 정한다(예: 상담 신청 버튼). 나머지는 조용하게.
- 토큰을 먼저 적는다: 색 4~6개(hex와 용도), 글자 크기 단계(예 14/16/18/24/32), 간격 단계(8/12/16/24/32), 모서리(버튼 10, 카드 16).
- 학원 로고 색이 있으면 그 색을 주인공 색으로.
- 피할 것: 흐린 배경 사진 위 글자, 모든 칸이 똑같은 둥근 카드, 알약 모양 버튼, 문단마다 들어오는 움직임, 이모지 아이콘.

## 2. 만들 때
- 글은 짧게. 한 줄에 한 뜻, 줄바꿈은 뜻 단위로. 단어 하나만 다음 줄로 떨어지지 않게.
- 버튼·칸 안 글자는 위아래 가운데(inline-flex + align-items:center). 입력창은 높이 고정 + line-height 맞춤.
- 터치 대상 44×44px 이상, 사이 8px 이상. 아이콘은 SVG, 아이콘 버튼에는 aria-label.
- 글자와 배경 대비 4.5:1 이상. 본문 16px 이상.
- 100dvh, env(safe-area-inset-*), flex/grid로 배치. 가로 스크롤 금지, 확대 막기 금지.
- 움직임은 transform/opacity만, prefers-reduced-motion 지원.
- 요메이트 기본 스킬 'ui-ux-design'이 있으면 레퍼런스 찾기에 같이 쓴다.

## 3. 배포 전 실측 (필수)
브라우저로 아래 크기마다 캡처하고, 요소 위치(getBoundingClientRect)를 숫자로 잰다.
- 크기: 휴대폰 390×844, 375×667, 360×800 / PC 1440×900, 1280×800
- 상태: 처음 화면, 공지 띠 있음, 상담 신청 칸 입력 중, 오류 문구가 뜬 상태, 아주 긴 반 이름
- 잴 것
  1. 겹침: 글자·버튼·사진 박스끼리 겹침 0
  2. 넘침: 가로 스크롤 0, 잘린 글자 0, 한 단어 줄 0
  3. 정렬: 버튼·입력창 글자의 위 여백과 아래 여백 차이 1px 이하
  4. 터치: 버튼 44px 이상
  5. 콘솔 오류 0, 깨진 이미지 0
- 하나라도 실패하면 고치고 다시 잰다.

## 4. 보고
고친 것, 잰 숫자(예: "버튼 위 14px / 아래 14px, 가로 넘침 0"), 확인한 크기, 남은 문제. 확인용 로컬 서버를 켰으면 끝나는 즉시 끄고 "서버 껐음"을 적는다.
